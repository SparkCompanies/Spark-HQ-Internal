How to get an Anthropic API key

Five-minute setup. You'll need a credit card on file with Anthropic but their starting credit is enough for hundreds of Jarvis queries.
1
Create an Anthropic account
Go to console.anthropic.com and sign up with your email. Use your Spark email so the bill goes to the right place.
2
Add billing
Click Plans & Billing in the left nav. Add a payment method. New accounts get $5 in free credit, which is roughly 500-1000 Jarvis queries depending on length.
3
Create an API key
Click API Keys in the left nav, then Create Key. Name it something like spark-hq-demo. Copy the key that appears — you can only see it once.
4
Paste it in
Come back here and paste the key into the field above. Hit CONNECT. Jarvis goes live for the rest of this browser session.
5
Set a spending limit (recommended)
Back in the Anthropic console, under Limits, set a monthly cap. Start with $20-50/month for demo. You can always raise it later. This prevents a runaway query loop from costing real money.
Cost reality check: Claude Sonnet 4 charges about $0.003 per 1K input tokens and $0.015 per 1K output tokens. A typical Jarvis query (say 500 input + 300 output tokens) costs about $0.006 — half a cent. A team of 10 firing 20 queries a day for a month is about $36. Real but small.

How to set up Amazon Bedrock for Claude

15-30 minute setup. Requires AWS account access. Result: Claude calls flow through your AWS account with full CloudTrail audit log.
1
Sign in to AWS Console
Go to console.aws.amazon.com. Sign in with the AWS account Spark uses. Make sure you're in a region where Bedrock has Claude: us-east-1, us-west-2, or us-east-2 are the safe bets.
2
Enable Claude model access in Bedrock
Go to Amazon Bedrock → Model access in the left nav. Find Anthropic Claude Sonnet 4 (and Opus 4, Haiku 4.5) and click Request access. Usually instant approval. Repeat for whichever models you want available.
3
Create an IAM user for Spark HQ
Go to IAM → Users → Create user. Name it spark-hq-bedrock. On permissions, attach the AmazonBedrockFullAccess policy (or a custom policy with just bedrock:InvokeModel if you want least-privilege).
4
Generate access keys
On that user's page, click Security credentials → Create access key → choose Application running outside AWS. Copy both the Access Key ID (starts with AKIA) and the Secret Access Key. You can only see the secret once — save it somewhere safe.
5
Paste into the Bedrock form
Come back here, paste the Access Key ID, Secret Access Key, and pick your region. Hit CONNECT. Test with the TEST CONNECTION button before going live.
6
Set CloudWatch alarms (recommended)
In AWS Console, go to CloudWatch → Alarms. Create an alarm on Bedrock → InputTokenCount with a daily threshold. Prevents a runaway query from burning unbounded tokens.
Why Bedrock for Spark: Every Claude call routes through your AWS account. CloudTrail logs the request. Prompts and responses stay in your VPC. When a client asks "where does your AI data go?" the answer is "our AWS account." Same Claude model quality as direct API, slightly higher cost (~5-10% AWS markup).
Important: Browser SigV4 signing puts your AWS secret key in browser session memory. For demo/prototype only. Production: the Spark HQ backend should use IAM role-based auth (no keys in browser).

How to set up Azure OpenAI

Requires Azure subscription with OpenAI access (which is now generally available). Result: GPT models routed through your Microsoft tenant, same AD as Spark HQ.
1
Sign in to Azure Portal
Go to portal.azure.com. Use your Spark Azure AD account (tenant e806542a-...).
2
Create an Azure OpenAI resource
Search Azure OpenAI → Create. Pick a subscription, resource group (use spark-hq-rg if you have one), region, and name (e.g., spark-hq-openai). Use the Standard pricing tier. Takes ~2 min to provision.
3
Deploy a model
Open the new resource → Azure AI Foundry portal → Deployments → Create new deployment. Pick a model (GPT-5, GPT-4o, or GPT-4o-mini). Give the deployment a name like gpt-5-spark. Set the rate limit (start at 100K tokens/min).
4
Get the endpoint and key
Back in Azure Portal, in your Azure OpenAI resource, go to Keys and Endpoint. Copy Endpoint (looks like https://spark-hq-openai.openai.azure.com) and one of the keys.
5
Paste into the Azure form
Endpoint, deployment name (the gpt-5-spark you picked in step 3), API version (default 2024-10-21 usually works), API key. Hit TEST CONNECTION first to make sure it works, then CONNECT.
Why Azure OpenAI for Spark: Same Azure AD tenant as Spark HQ login. IT only deals with one cloud. Microsoft enterprise agreements often include OpenAI credits. Tradeoff: GPT-5 instead of Claude, different model personality.
Note: Azure OpenAI uses GPT models, not Claude. Responses will feel slightly different — usually more verbose, more eager to add caveats. Test with your team before committing.
